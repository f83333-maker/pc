feat(scale-layout): 字号放大 + 修复 iPhone 底部空白 + 取消 800 断点

按用户反馈三件事一次到位：

1) 取消 800 断点（assets/user/css/index.css 第 344-460 行）：
   - 删除原 @media (min-width: 800px) 包装，把里面横排导航规则提到无条件应用
   - 整体删除 @media (max-width: 799.98px) 折叠菜单块（不再需要）
   - 副作用：所有设备永远使用桌面横排导航，移动端缩放后视觉一致

2) 字号放大（两个 Header.html 内联脚本）：
   - 引入平台检测 isIOS = /iPad|iPhone|iPod/.test(UA) 或 Mac+touch
   - DESIGN_WIDTH 默认值改为分平台：
     · iOS    = 270  → ratio≈1.456 → 字号视觉 ~3x（用户要 3-4x）
     · Android = 540 → ratio≈0.728 → 字号视觉 ~1.5x（用户要 1.5x）
   - 暴露三个全局开关供单点微调，无需改 JS：
     · window.__SCALE_IOS_WIDTH__ = N
     · window.__SCALE_ANDROID_WIDTH__ = N
     · window.__SCALE_DESIGN_WIDTH__ = N（统一覆盖，优先级最高）
   - GUARD_MAX=1024，screen<1024 才介入；桌面端零侵入逻辑保持

3) 修复 iPhone 短内容时底部大块空白（增强 fix CSS）：
   - 把 body 的 background 移到 html 上（同一渐变 + bg.jpg）
   - body 设 background:transparent，min-height:0!important，
     display:block!important（解除 flex 撑开），#pjax-container 从
     flex:1 0 auto 改为 0 1 auto
   - html 同样 min-height:0!important，背景 attachment:scroll
   - 加 overscroll-behavior:none 关闭 iOS 橡皮筋
   - 原理：Safari 在 viewport=N + initial-scale=ratio 下会把 layout
     viewport 高度算成 物理高/ratio（iPhone 14 Pro 可达 1738px），
     若 body 没撑满，body 之外区域会显示 body 背景延伸 ——
     现在 body 透明，html 接管背景显示，视觉上不会出现"色块空白"

  - Android: viewport=540, platform=android, base=540, ratio=0.7278
  - html.min-height=0, body.min-height=0, body.display=block,
    body.background=none, html 接管背景图, #pjax-container flex=0 1 auto
  - 桌面 1920：脚本完全不介入，零侵入
